# 题目二现场答辩讲稿

这份讲稿按“学习工作台 → 实验 / 评估”两个视图的顺序写，正常语速约 4 分钟。不要背术语；每说一个结论，就把鼠标指向页面上对应的字段。

## 演示前准备

1. 提前把密钥链接到 `.private/deepseek_api.txt`，双击 `打开题目二教学Agent.command`。
2. 确认页首显示 `DeepSeek` 和 `deepseek-v4-flash`，不要在降级状态下声称正在调用模型。
3. 保留默认的“动态规划的状态与转移”案例，现场更稳定；若老师要求新题，再修改目标。
4. 浏览器缩放保持 100%，默认停在“学习”视图；右侧“学习检查器”保持展开。

## 0:00—0:30：先说清题目要解决什么

指向中间的空对话区和左侧三个学习阶段，说：

> 题目要的不是让大模型一次写出整段教案，而是一个能实时互动的教师 Agent。学生每回答一次，系统才做一次判断：先更新学生状态，再选择或切换 Teaching Skill，最后只生成当前下一步。达到目标就结束；没有进展就停止并转给教师。

接着用一句话说清技术方案：

> 我们用 DeepSeek V4 Flash 处理自然语言理解和本轮教学话语，用确定性控制器守住 Skill 白名单、状态范围和停止条件，所以既能灵活回答，也不会让模型随意改状态或无限对话。

## 0:30—1:05：01 目标与画像

指向左侧“新建会话”区域：

> 这里输入的是本次教学目标，不是固定脚本。默认目标是让学生能解释动态规划状态、写出转移，并判断新问题是否适合动态规划。右侧四个初始值分别表示前置、概念、过程和迁移的内部状态。它们只用于控制教学流程，不是学生考试分数。

展开“学生画像”，补充：

> 画像只保留教学需要的信息，比如初学者、偏好直观例子和逐步提示。教师输入的这些基础字段不会被模型覆盖；学生回答后，系统会另外追加一条带证据、置信度和“待确认”状态的候选画像，供教师复核，而不是把模型猜测静默写成永久事实。

点击“开始实时教学”。

## 1:05—1:40：02 第一轮只生成一个动作

指向中间第一条教师消息，再指向右侧当前主 Skill、支持 Skill 和选择依据：

> 现在系统只生成了第一个动作，并停下来等学生回答。这里能看到主 Skill、组合的支持 Skill和选择原因；一个主 Skill 负责本轮教学意图，支持 Skill 只约束提示力度或等待方式，所以组合 Skill 也不会一次输出多个回合。

再指向 `decision origin` 或运行状态：

> 这一轮的来源显示 DeepSeek，说明它确实完成了诊断、路由和本轮话语生成。如果 API 失败，页面会明确写成 deterministic safety fallback，我不会把降级结果冒充模型结果。

## 1:40—2:45：连续三轮互动，展示 Skill 动态切换

根据系统当前问题选择意思相符的回答，不必逐字照搬。下面三句可以直接粘贴。

第一条，先给出一个有用的前置信号：

> 我知道递归可以把大问题拆成更小的问题，但我还不知道 dp 数组的每一项应该表示什么。

提交后说：

> 系统没有只看“对或错”，而是把它判断为部分理解，更新置信度、证据和下一关注点，然后重新选下一轮 Skill。右侧的候选画像也新增了一条本轮观察，但它仍标为未确认。

第二条，主动制造一个可定位的误解：

> 我觉得 dp[i] 只需要看 dp[i-1]，因为第 i 级一定是从前一级走过来的。

提交后指向“判断证据”“误解记录”和 Skill 切换标记：

> 这句话包含一个明确错误规则：忽略了可以跨两级到达。系统把误解和原话证据记下来，并优先切换到误解对比纠错或理解检查，而不是继续机械讲原来的内容。这就是动态决策。

第三条，给出纠正后的回答：

> 还要考虑从 i-2 级跨两级到达，所以状态应该同时看 dp[i-1] 和 dp[i-2]，也就是 dp[i]=dp[i-1]+dp[i-2]。

提交后说：

> 新证据支持后，误解可以从 active 变为 resolved，掌握状态和 Goal 进度随之变化，Agent 再决定进入练习、理解检查还是迁移。后续轮次并不是开始时预先写好的。

如果现场模型没有按预期切到某个具体 Skill，不要硬说它错了。先解释页面给出的理由；需要演示人工接管时，输入 `/+skill 误解对比纠错`，下一轮后再输入 `/auto`：

> 教师可以持续锁定一个 Skill，直到输入 `/auto` 恢复自动路由；页面会留下 manual override 标记，人工选择不会算成 Agent 自动命中。

## 2:45—3:35：03 学生状态和候选画像为什么不是黑箱

指向右侧“学习检查器”中的“当前理解”和“上下文记忆”：

> 题目要求显式维护四类信息，这里都能看到：当前掌握、活跃或已解决的误解、本轮理解信号、下一步教学重点。上下文也不是把聊天全部塞给模型，而是分成固定目标、当前计划、近期工作记忆、较早检查点、知识状态和未确认候选记忆；这里能看到保留了哪些轮次和用了多少预算。

指向“Agent 候选画像（待确认）”：

> 这里是根据有效 DeepSeek 回合形成的最新候选画像，展示回答质量、参与度、下一重点、置信度和是否需要人工复核。每条都是 `candidate_unconfirmed`，最多保留 12 条；低置信度会醒目标记，规则降级不会生成候选，教师原来填写的水平和偏好也不会被覆盖。

指向 Goal 进度：

> Goal 被拆成前置、概念、过程和迁移四个可观察步骤。系统只有看到对应回答证据才推进；这个进度是流程控制，不是学习效果结论。

## 3:35—4:20：04 评估结果怎么讲

点击顶部“实验 / 评估”，先指向在线开发 benchmark：

> 第一层评估检查自由文本理解。28 个作者构造案例覆盖四个学科和七类回答，第三次在线开发运行的信号 Accuracy 是 0.892857，Macro-F1 是 0.875325，允许主 Skill 命中率是 0.785714。它比常量标签和固定诊断 Skill 基线高，但这是开发集，不是独立锁箱，也不是真实学生准确率。

再指向自适应 Agent 与固定单 Skill表：

> 第二层是四条结构化轨迹的机制回归。自适应 Agent 的允许决策匹配率是 0.916667，终止匹配率是 1；固定基线整段只用逐步支架。这里的模拟增益差是 16.9165，只说明状态机按 fixture 工作，不能说学生成绩提高了 16.9 分。

最后指向前测、后测与迁移测：

> 第三层提供真实学习实验需要的记录接口，可以算前后测、迁移测和可选延迟测。页面当前的 0.4 到 0.8 是作者构造演示，只证明接口能算，真实学习效果还需要学生实验。

## 4:20—4:45：05 主动交代边界并收尾

指向评估视图中的证据边界，再打开页首模型/Skill 状态：

> 默认 v2 库有 13 个主 Skill 和 3 个支持 Skill。它使用 neural-v1 的九环节和十三策略本体，但 neural-v1 的证据物化门禁目前没有通过，所以我们把它明确标为 provisional，没有把候选写成已确认的视频共识。当前完成的是可运行、可审计、可回归的教学闭环；下一步是专家双人复核、锁箱跨 session 测试和真实学习者实验。

最后一句：

> 这个项目最核心的贡献，是把第一题的 Teaching Skill 从静态文档变成了能根据学生反馈实时选择、组合、切换并安全终止的执行系统，同时把“已经验证什么”和“还没有验证什么”明确分开。

## 老师常见追问与一句话回答

### 1. 你们到底用了什么 Agent？

> 是 DeepSeek V4 Flash 语义与生成层加确定性状态和安全控制层组成的混合 Teaching Agent，不是一次普通聊天调用。

### 2. 为什么不让 DeepSeek 控制全部状态和终止？

> 自由文本理解需要模型，但 Skill 白名单、数值边界和停止条件必须可验证，否则模型可能越权、重复或无限对话。

### 3. 这真的不是提前生成好的对话吗？

> 每个 `step` 只接收当前一条学生回答并返回一个下一动作，后续内容在收到反馈前不存在。

### 4. 学生状态是怎么得到的？

> DeepSeek 从当前回答和相关历史提出带置信度与证据的诊断，控制器再按受限规则更新四维状态和误解生命周期，并把有效诊断追加为待确认画像候选。

### 4.1 Agent 会不会擅自修改老师填写的学生画像？

> 不会；教师字段保持原值，Agent 只在独立的 `adaptive_observations` 中追加待确认候选，低置信度必须人工复核，当前也不会跨 session 保存成长期画像。

### 4.2 你们真的做了上下文吗？

> 做了，而且不是简单拼接聊天记录。每轮只有一个受预算约束的六层上下文：目标与教师画像、当前计划、近期相关回合、较早历史检查点、掌握与误解状态、未确认候选记忆；本轮回答只出现一次，所有关键状态都有来源指针。多知识点目标只标当前动作真正涉及的知识点，默认最多保留 6 个相关回合、总计 14000 字符；超长会话会逐层裁剪，旧内容被压缩但不会由模型编造摘要。

### 5. 你们的准确率是不是 89.29%？

> 89.29% 只是在 28 个作者构造、post-hoc 开发案例上的七类信号 Accuracy，真实学生和部署准确率还没有建立。

### 6. 为什么 Skill 命中只有 78.57%？

> 这是严格命中作者预先给定的允许集合；结果说明路由有开发价值也有改进空间，下一步要用专家锁箱标签验证。

### 7. neural-v1 不是已经训练了吗，为什么还写 provisional？

> 训练确实完成，但 54 个 OOF 原子都没有通过证据物化门槛，所以本体可用于暂定执行，不能冒充已确认课堂共识。

### 8. Skill 是从第一题来的吗？

> v2 用 neural-v1 的九环节和十三策略本体组织 12 个操作包装，另外 4 个研究补充 Skill 单独标源，没有伪装成视频发现。

### 9. 多模态在哪里？

> 多模态用于第一题的视频证据抽取和 neural-v1 来源建模；题目二当前实时输入是文本对话，不能把它说成实时视频教学 Agent。

### 10. 如何证明 Agent 比普通聊天好？

> 当前有固定单 Skill、常量标签和固定诊断 Skill 基线，证明机制和开发集表现更好；要证明真实教学更好仍需锁箱和学生对照实验。

### 11. 系统会不会直接把答案告诉学生？

> 提示词要求支架式单步行动，验证器拦截明显最终答案表达，但还需要外部行为评测证明复杂场景下的泄露率。

### 12. API 断了怎么办？

> 系统会重试并进入明确标记的规则安全降级，也可以关闭降级让本轮直接失败；降级结果不会伪装成 DeepSeek。

### 13. 学生隐私怎么办？

> 页面和会话服务只在本机，远程只发送必要文本并替换常见直接标识符；但模式脱敏不是完全匿名，真实使用仍需授权和数据最小化。

### 14. 真实学习效果做了吗？

> 目前完成了标准化前后测、迁移和延迟测接口，随附数据是演示 fixture；真实效果需要合规学生实验和对照组。

### 15. 现在最大的短板是什么？

> 最大短板不是工程闭环，而是外部效度：neural-v1 证据门禁、专家双人路由标注、跨 session 锁箱和真实学习效果都还未完成。
