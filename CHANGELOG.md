- Added the complete task-two adaptive Teaching Agent. DeepSeek V4 Flash performs one logical diagnosis-routing-action operation per turn, with bounded transport retries permitted, and returns one teaching action; a deterministic controller owns four-dimension state updates, misconception lifecycle, goal progress, primary/support composition, manual `/+skill` and `/auto` control, and success/unable termination. Each primary Skill's `supporting_skill_ids` is a hard support-composition allowlist. Online plans, manual locks and deterministic fallback share machine gates for Skill ID/role, applicable signal, evidence-backed correction, selected high-risk stage/material preconditions, material availability, primary/support repeat limits, the primary support allowlist and support-local eligibility; absence of any executable Skill stops and escalates. Other natural-language execution-contract clauses remain prompt/audit constraints and are not claimed to be fully machine-understood. The loopback/no-store dashboard exposes every decision and an explicit degraded fallback instead of replaying a pre-generated dialogue.
- Hardened the task-two Agent around real session and semantic failure cases. The dashboard now keeps up to 16 isolated in-memory Teaching Sessions, restores one session from an opaque browser handle, creates profile changes transactionally, rejects admission when every bounded slot is actively locked, and binds every turn to the session, round, current question, context version, profile revision and idempotency key. A profile replacement also binds the old round, question, context version and profile revision while holding that Session lock, so a stale replacement cannot discard a newly committed turn. Session state is process-local only: a service stop or restart loses every Session, and an old browser handle cannot restore it. Free-text prior context is stored as `background_history`, labelled as teacher-provided unlabeled background, and cannot fabricate a student signal or change initial learner state. A shared question-contract rubric distinguishes a correct answer, a partial answer and a related term that does not answer the current question; exact accepted concepts override inconsistent model labels, while a bare neighboring concept can no longer create a durable misconception or trigger a correction Skill. Assessment provenance now distinguishes raw DeepSeek output, deterministic-contract normalization, active-question exact match and safety fallback. Unconfirmed adaptive-profile candidates without a grounded student excerpt are forced into human review. Manual Skill locks persist until `/auto` but are released by applicability, correction-evidence, repeat-limit or fallback guards. The UI now includes three clearly synthetic student portraits, mathematically labelled mastery rings, keyboard-accessible profile and inspector controls, persistent errors and responsive 44-pixel interaction targets. In addition to static UI contracts and a privacy-safe HTTP black-box runner, a Playwright-driven real Chrome runner now advances the old Session outside the UI before profile replacement, observes exactly one expected stale-guard HTTP 400, and verifies guard resynchronization, a fresh start idempotency key, exactly one retry and a successful profile-B commit; it also covers the printed-text image turn, mastery/handle isolation, manual-Skill non-inheritance, refresh/form recovery, evaluation navigation and responsive widths while emitting only an aggregate receipt. The expected 400 is counted separately from unexpected console/network failures. This is one controlled concurrency path and reproducible runner evidence, not arbitrary-concurrency coverage or a claim based on Codex's in-app browser availability. On 2026-08-06 both the local deterministic backend and the real `deepseek-v4-flash` backend passed the recorded Chrome and HTTP lifecycle acceptances; the current working tree also passed fresh local release verification, but none of these results is claimed as cross-browser, assistive-technology, deployment or learning-effect validation.
- Added bounded learner answer-image evidence to the task-two Agent. PNG/JPEG/WebP media is validated and processed only in local memory and a temporary directory; supported macOS hosts prefer an on-device Apple Vision extractor and fall back to Tesseract when Vision is unavailable, fails or returns no text, while other platforms use Tesseract when installed. The raw image is never sent to DeepSeek: only a length-bounded OCR envelope, passed through the same known-identifier pattern redaction as typed student text, enters the remote teaching context. Attachment IDs are bound to session/question/round/profile/context guards, are idempotent and single-use, and stale or cross-profile reuse fails closed. Formula/code-like, empty or numerically low-confidence OCR always requires student confirmation even if an incoming attachment record claims otherwise; generic typed assertions such as “the photo is obviously correct” cannot bypass this gate. Such a turn is normalized to partial/ambiguous at zero confidence, cannot raise mastery or resolve a misconception, clears unexecuted support modifiers, and uses only self-explanation or Socratic understanding-check actions. The controller prefers self-explanation, rotates to the Socratic check when the former reaches its consecutive `max_repeat`, and preserves the same contract through deterministic fallback. Evidence grounding now tolerates only case and whitespace layout changes when the model quotes multiline OCR, while returning the exact source span; paraphrases and fabricated evidence still fail closed. No handwriting, formula or deployment OCR accuracy is claimed. Live unit tests cover the two-Skill confirmation contract, loopback tests cover attachment binding/consumption/staleness, and the Playwright real-browser runner separately covers an in-memory, high-contrast printed-text image-only success path without persisting real learner media or OCR text in public receipts.
